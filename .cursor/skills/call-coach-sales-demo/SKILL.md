# Call Coach：銷售 DEMO／諮詢（非轉錄技術）

## 與產品功能的對應

| 使用者需求 | 產品功能 |
|---|---|
| 手打式「業務[00:31]問…」複盤 | 網頁「一鍵轉開發重點」（本機規則 + 可選 AI 精修） |
| 通話品質分析 | 上傳 SRT → 六步驟／五層／信任感 |
| DEMO 錄影逐字稿 | 本機／Azure／遠端 GPU 轉錄 |

**諮詢腳本任務通常不需要改 `demo-workspace`**，除非要改開發重點格式或 UI。

## 諮詢結構（60～90 分鐘）

1. **開場**：確認設備、重述上次共識、不強推
2. **挖掘（60%）**：開放題，讓客戶說；對技術客戶用「可驗收交付」取代空泛 FDE
3. **釐清**：一句 MVP（例：「4 週內週報自動化產出 X」）
4. **Diagnose**：口頭 A／B／C 適配（敢判 C 建立信任）
5. **Demo**：只 demo **他的場景**，不要從頭播學院簡介
6. **Decision**：下一步具體（資料清單、二訪、夫妻場 15 分鐘）

## 常見客戶原型（本對話出現過）

| 原型 | 主線 | 成交關鍵 |
|---|---|---|
| 裝修／一人公司＋AI 報價 | 落地工具鏈，非直播課 | 同理踩坑、不否定既有 ChatGPT 串接 |
| 共有財產、月預算 4000 vs 65000 | 報表自動化 MVP | 給**太太看得懂的一頁**，不要 FDE 術語 |
| 8 年平面接案、客群太像 | 定義「可賣的 AI 服務名稱」 | 共創 4 週作品集案例，再談課程 |

## 開發重點筆記格式

```
業務[mm:ss]摘要
客戶[mm:ss]短答

【業務氛圍】業務[起]~[迄]「原話」→ 營造什麼
【客戶語調變化】客戶[時間]「原話」→ 從…轉為…
```

AI 精修需 Gemini + 同意；本機規則版不上傳。

## Agent 注意

- 區分「寫 code」與「寫諮詢稿」；後者用本 skill，不要改轉錄 pipeline
- 若使用者同時抱怨 GPU 轉錄失敗，切到 `call-coach-transcribe-debug` 與 `call-coach-local-gpu`
